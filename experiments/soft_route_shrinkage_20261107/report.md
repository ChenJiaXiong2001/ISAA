# soft-route 单人校准与权重收缩筛查

本轮只使用已保存的 soft-route / matched-control 训练校准输出，不读取正式验证
标签，不训练，不占 GPU。清洁校准集共有 351 条，全部来自同一受试者 P025、同一
设置 S008、三台相机和两个重复 R001/R002；按重复分层后分别为 175 和 176 条。
多数类别只有 6 条，1 个类别在单折拟合集中没有样本。该划分检查的是单人内重复
稳定性，不是跨受试者泛化。

预先固定比较原始 alpha=0、伪计数 alpha=1、alpha=5 和等权 0.5。收缩权重为
`(HF正确数+alpha)/(HF正确数+BF正确数+2*alpha)`。只有 soft-route 候选在两个留出
重复上都不下降、且合计至少多对 3 条，才允许选择 alpha；未达到条件则不把任何
参数带到正式验证。

| 模型 | 留出 R001 alpha=0 / 1 / 5 | 留出 R002 alpha=0 / 1 / 5 | 合计相对 alpha=0 |
| --- | ---: | ---: | ---: |
| matched control | 134 / 135 / 137 | 133 / 137 / 138 | alpha=1 +5，alpha=5 +8 |
| soft-route candidate | 134 / 134 / 135 | 133 / 133 / 134 | alpha=1 0，alpha=5 +2 |

soft-route 的 alpha=5 虽然两折均为正，但合计仅多 2 条，低于预设至少 3 条
门槛；alpha=1 没有增益。因此 `selected_alpha = None`，没有进行正式验证评估，
也没有利用验证结果挽救或选择方案。control 的较大收益只作描述，不能替代
soft-route 的候选证据。

机制上，单人每类最多 6 条使权重明显不稳定。按两折拟合的 soft-route 计数：
每折均有 1 类无拟合样本；HF/BF 任一头在该类计数为零的极端类别分别为 17 和
17；两折权重有 36/60 类变化，平均绝对差 0.1792，中位数 0.1，最大差 1.0，
有 23 类变化至少 0.25、11 类至少 0.5。control 的对应平均差 0.1858，39 类
变化，19 类至少 0.25，9 类至少 0.5。收缩确实消除了零/一端点，但没有在这个
单人重复留出协议中达到预先规定的实质准确率门槛。

checkpoint 保存的 routing counts 与各自 351 条 clean logits 重新计算的 HF/BF
正确数完全一致；缓存 shape、成员顺序、标签与 checkpoint SHA 均检查通过。原始
soft-route paired 输出及 logits 保存在服务器实验目录，复制的校准汇总、逐样本
结果和机制 JSON 在本目录。由于单人、重复共享、样本很少，收缩结果不能说明
跨人或完整训练准确率提升；本轮结论是“不选择参数并停止扩展”，不是证明所有
收缩方法无效。
