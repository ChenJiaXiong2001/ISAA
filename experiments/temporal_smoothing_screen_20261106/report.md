# 置信度加权时间平滑的 CPU 机制筛查

固定 256 条 epoch-83 训练校准样本，沿用同侧 5 原始帧合成遮挡。候选对所有
133 个点中连续三帧均为正分且帧有效的点，按 `[1,2,1] * score` 加权平滑
坐标；不填缺失、不更改分数、序列两端不动。该方案需要下一帧。以未遮挡的
压缩后坐标为参考，距离除以未遮挡肩髋尺度；参考不是几何真值。

| 样本点范围 | 点帧数 / 片段数 | 未平滑受损位移均值 | 平滑后受损位移均值 |
| --- | ---: | ---: | ---: |
| 遮挡区域且压缩后仍在 clean 和受损中可见 | 297 / 12 | 0.011432 | 0.011432 |
| 其中肩髋锚点 | 26 / 12 | 0.005368 | 0.005368 |
| 其中其余身体点 | 25 / 12 | 0.010879 | 0.010879 |
| 其中手部点 | 246 / 11 | 0.012130 | 0.012130 |
| 其他两输入均可见点 | 2,835,346 / 256 | 0.00000069 | 0.004683 |

这 297 个受影响点均没有变近或变远；其余点的 256 条片段累计位移均增加，
对 clean 数据单独平滑的平均位移为 0.004711。三帧都有效的规则使连续缺失
边缘往往无法平滑，故在此设定下并未修复遮挡影响。上述位移是相对于原始
未遮挡输入的变化，并非动作识别准确率，也不能证明更接近真实位置。

该固定规则在当前 256 条、这一合成遮挡代理上没有显示收益，不建议据此占用
GPU；结论不排除其他平滑器、错误类型或数据的收益。点帧高度相关，候选
未在任何模型预测或真实遮挡上验证。没有使用验证集或标签调参。

`test_smooth.py` 使用逐帧逐点标量公式核验向量化平滑、边界、缺失掩码和分数
保持，测试通过；逐片段和三个身体区域分解见 `result/`，又用独立 PowerShell
重新汇总各类点帧数和位移均值。遮挡脚本与仓库文件 SHA256 一致，运行使用
`../anchor_natural_confidence_20261106/rtmw_zip_dataset_snapshot.py` 记录的
旧实验数据加载器及无增强路径；可复现协议在 `protocol.md`。
