# 拒识筛查：准确率与人工复核量

**权重口径更正：** 本目录以下原始结果使用校准缓存重新计算的准确率比例
权重；它与 checkpoint 保存的权重在 A011 和 A012 两类不同，因此不能将其
描述为 checkpoint 冻结权重的结果。差异原因尚未确定。使用 checkpoint 权重
重算后，缓存全部样本准确率为 15593/16306；5% 分位拒绝 818 条、捕获
356/713 个错误、接受样本准确率 97.6950%；10% 分位拒绝 1546 条、捕获
510/713 个错误、接受样本准确率 98.6247%。重算及逐类计数核验见
`../disagreement_rejection_20261106/`；以下旧结果保留供追溯。

固定 epoch-83 HF/BF checkpoint，使用原准确率比例权重和既定 50% 算术、
50% 归一化几何融合。在 3,191 条训练校准缓存的最大融合概率上，预先固定
5% 和 10% 分位点为阈值，分别为 0.616560 和 0.741206；只接受不低于阈值的
预测。阈值不使用验证标签，但同一校准集也用于确定原融合权重。

所有验证样本的融合准确率仍是 15592/16306 = 95.6212%，筛选不改变它。
20 名受试者聚类重采样的覆盖率 95% 区间分别为 [93.8622%, 95.4703%]
和 [88.9172%, 91.3299%]；接受准确率区间为 [96.9693%, 98.1209%] 和
[97.9652%, 98.9817%]。区间固定阈值，不包含阈值选择和重复探索的不确定性。

不同行为和受试者差异明显：5% 阈值下 P036 接受 327/356，接受准确率仅
92.3547%；A011 接受 235/276，接受准确率仅 83.8298%。10% 阈值下分别为
94.5161% 和 89.2157%。因此低置信度可以帮助安排复核，但剩余高置信错误
仍然显著，且其是否有用取决于实际复核流程和成本。

结果来自已有 CUDA logits 缓存，缓存中的总体准确数与新 CUDA 前向可相差少量；
验证集已反复用于探索，不能作为独立盲测。缓存 SHA256 和逐受试者、逐类别
结果见 `result/summary.json`，逐样本见 `result/predictions.csv`，固定协议和
CPU 可复算代码见本目录。现有同侧遮挡输出只有类别没有分数，不能据此计算
遮挡拒识效果；`evaluate_occlusion_scores.py` 准备在 GPU 空闲后以同一既定
遮挡协议重新提取分数并检查输出与预测一一对应。

独立 `audit.py` 用双精度概率空间重新计算融合、两个分位阈值、全部预测及
20 名受试者和 60 类统计，均与结果一致；相关脚本通过 Python 语法编译。
