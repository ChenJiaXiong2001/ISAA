# HF/BF 融合方案完整比较

2026-11-03（UTC+09:00）。已完成两个检查点、每个 56 套设置，共 **112 套**完整验证；没有重新训练骨干、分类头或门控网络。

## 结果

本轮验证集最高观察结果为 **95.3330%（15,545 / 16,306）**：epoch 83、两个头分别做温度校准、动作准确率权重指数 γ=2。相比同批输出上的原比例加权 γ=1（95.2839%，15,537 条）增加 **8 条、0.0491 个百分点**，修正 33 条同时新增 25 条错误。

不过，完全按内部校准准确率选择的全局方案是 **epoch 100、温度校准、γ=4**，在正式验证集上为 **95.1797%**。epoch 83 自身按校准选择的是原温度 γ=2，正式验证为 **95.2104%**。因此 95.3330% 是本轮多方案比较中的探索性最高值，不能作为按校准预选方案的成绩。收益很小，当前没有充分依据把原 γ=1 比例融合替换为更复杂的动态融合。

## 按样本置信度动态融合

测试三种可靠性：最大预测概率、前两名概率差、`1−归一化熵`。各测试 β∈{0.5,1,2}、动作先验 γ∈{0,1}，并分别比较原温度和校准温度。每个样本、每个候选动作的有效 HF 权重为：

```text
W_c = accuracy_HF[c]^gamma / (accuracy_HF[c]^gamma + accuracy_BF[c]^gamma)
w_n,c = W_c * reliability_HF[n]^beta /
        (W_c * reliability_HF[n]^beta + (1-W_c) * reliability_BF[n]^beta)
q_n,c = w_n,c * P_HF[n,c] + (1-w_n,c) * P_BF[n,c]
P_fused[n,c] = q_n,c / sum_c(q_n,c)
```

零和准确率使用等权；可靠性下限为 1e-6。全部概率算术融合采用稳定的 log 域实现。

| 动态方法 | epoch 83 最高观察 Top1 | 对应设置 | epoch 100 最高观察 Top1 |
| --- | ---: | --- | ---: |
| 最大概率 | 95.2349% | 原温度、γ=1、β=0.5 | 95.1613% |
| 前两名概率差 | 95.1613% | 原温度、γ=1、β=0.5 | 95.1122% |
| 归一化熵 | 95.2901% | 原温度、γ=1、β=0.5 | 95.1981% |

这些同样是各分组在正式验证集上的最高观察值。动态最大概率和概率差均未超过原比例融合，熵融合只多 1 条正确，未显示有实际意义的稳定优势。

## 实现与核验

- 新增缓存入口 [cache_face_pair_logits.py](../../../tools/cache_face_pair_logits.py)：逐一严格加载 epoch 83 / 100，校准 3,191 条、验证 16,306 条，每条都核对成员顺序、标签和 SHA256；模型所有 state_dict 张量在推理前后完全相同。
- 模型继续强制 CUDA Inductor 编译。Body/Hand 编码、池化、两个分类头及原融合编译，Face LocalSTBlock 保留原 baseline eager 边界。新增 [face_pair_fusion_sweep.py](../../../tools/face_pair_fusion_sweep.py) 的静态、温度、置信度与新融合全部 `torch.compile(fullgraph=True)`，无整模型 eager 回退。
- [run_face_pair_fusion_suite.py](../../../tools/run_face_pair_fusion_suite.py) 执行固定候选表、校准、选择与正式评估，输出 Top1/Top5/NLL/Brier/ECE、逐类支持数、混淆矩阵及每候选预测。
- [unittests.log](unittests.log)：9 项测试全部通过，含 CUDA Inductor fullgraph 对照、独立概率算术公式、头交换对称、零计数与硬路由边界、动态退化、温度 NLL 核验。
- [audit.json](audit.json)：独立用保存的预测/标签复核 112 套正确数、混淆矩阵总数/各类支持数、两头覆盖率及逐样本净增。所有导出计数一致；融合概率归一化最大误差约 4.17e-7。
- 使用保存的原校准计数构造动作先验，保持与之前方案一致。本轮重新收集的 epoch 83 BF 校准计数在两类上分别有 +1/−1 的浮点运行差异，HF 无差异；epoch 100 两头校准计数均与保存值一致。差异保存在 [cache_report.json](cache_report.json)，未据此改写检查点。
- 本轮 epoch 83 原比例融合为 15,537 条，之前完整重评为 15,536 条，差 1 条；保留原 CUDA/TF32 与编译设置而未强制确定性。所有方案统一使用本轮同一批 logits 比较，避免把不同运行之间的浮点差异计为策略收益。
