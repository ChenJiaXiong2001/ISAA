# 原最佳模型 + 动作候选控制的手—身体交互

独立变体：`best-action-hand-body`。所有旧模型、旧入口及旧配置保留。
继承 `BodyLocalHandCTRWideRelativeFusion` 并原样调用其 forward：身体输入、头部输入、
手部六通道、共享手部 CTR-GCN、双手距离及方向、所有原融合和分类模块均保留。
新增参数随机初始化，不加载原最佳模型或其他模型权重；训练入口和通用入口都拒绝 `--init-checkpoint`。

## 新分支

1. 原路径独立输出动作概率。对候选动作组的概率求和，得到每个身体区域的候选强度。
   路由概率 detach，防止原分类路径通过改变概率逃避交互；原路径仍由分类损失训练。
2. 推理时，仅候选强度达到阈值的区域进入距离计算。每只手完整保留 21 节点，
   仅与本人的候选非手部区域交互，不添加跨人的连接。
3. 四个躯干点（5、6、11、12）提供共同中心与尺度，得到全身相对坐标。
   新分支采用归一化相对坐标；原路径原有坐标处理不改动。
   距离小于 0.4 个躯干长度进入，超过 0.48 退出；缺失帧或无效节点立即断开。
   排除手根节点与身体腕部的重复点对。
4. 只对通过筛选的节点和边运行神经编码。边特征含相对位移、距离、方向、相对速度、
   距离变化和置信度。按手节点、区域归一化，避免面部节点多而主导融合。
5. 绝对躯干上下文只参与交互门控，不增加独立的躯干分类残差。
   距离接近程度、节点有效性与学习门控共同控制消息；左右手分别激活。
6. 按区域保留时序交互特征，独立分类头产生修正分数。
   `最终 logits = 原路径 logits + interaction_strength × 候选门控 × 交互修正`。
   修正仅写入该区域配置的动作类别；一个动作对应多个区域时取平均。
   没有候选、没有有效邻居或 warmup 阶段，修正严格为零。

默认是 NTU60 的第一轮手工区域映射，而非已验证的最优映射：

| 区域 | 动作编号（从 1 开始） |
| --- | --- |
| 头部/面部 | A001、A002、A003、A004、A018、A019、A020、A021、A028、A032、A037、A038、A041、A044、A047、A048 |
| 躯干 | A014、A015、A025、A040、A045、A046 |
| 左/右上肢 | A014、A015、A040 |
| 左/右腿、左/右脚 | A016、A017 |

电话动作是 **A028**；A029 是玩手机/平板，本轮没有映射。
阅读 A011、写字 A012、搓手 A034 等不配置新增交互区域。
“不配置”表示这些类别不能触发交互，也不直接接收交互修正；
当预测不确定且其他候选组概率超过阈值时仍可能启用交互，其他类别的修正也可能改变最终排名。
因此不能据此承诺阅读/写字准确率一定保持。

配置见 `configs/best_action_hand_body.json`：`region_actions` 使用 NTU 的 **1 基编号**；
省略的区域关闭，空列表关闭对应区域。自定义类别集应提供自己的映射。
NTU120 默认仅覆盖上述 NTU60 动作，其余动作需另行配置。

## 从头训练

```bash
python train_best_action_hand_body.py --device cuda
```

默认数据 `data/ntu60_skeletons_rtmw.zip`，NTU60 XSub，64 帧、2 人、batch 32、65 epoch；
原 SGD/Nesterov 学习率协议保留。独立输出到
`outputs/best_action_hand_body_ntu60_xsub/<run>/`，保存配置、源代码、日志与 best/last checkpoint。

| epoch | 行为 |
| --- | --- |
| 1–5 | 仅原路径分类；新分支不编码边、不接收梯度 |
| 6–15 | 修正强度从 0.1 增到 1；联合训练 |
| 16–65 | 全强度联合训练 |

训练期间使用软候选门控，允许所有配置区域通过距离筛选，避免早期误判切断学习。
额外探索量从 0.09 逐步减到 0；它只影响训练、不使用真实标签，也不加入推理。
验证和推理始终使用候选阈值（默认 0.15），训练/推理策略有差异，需要通过验证评估。
门控和修正强度均由配置/检查点重建；保存强度确保 ramp 期间的 checkpoint 复现对应验证结果。

联合训练损失：

`L = CE(最终输出) + 0.5 × CE(原路径输出) + 0.2 × CE(交互辅助输出)`。

warmup 仅计算一次原路径 CE。交互辅助损失只覆盖真实类别在映射中且相应区域
存在有效邻居的训练样本；标签只在损失函数中使用，forward 完全不接收标签。
辅助分类直接监督未乘动作候选概率的交互特征，减少原路径低候选概率造成的梯度饥饿。
新输出头小随机初始化，使用 LeakyReLU 与 LayerNorm；新增参数默认 weight decay 为 1e-5，
原模型参数仍为 4e-4。这些措施需结合实际梯度和消融验证，不能保证不会退化。

训练默认且强制启用 `torch.compile`，无需额外传 `--compile`；专用入口与通用入口均拒绝
`--no-compile`。原最佳主干保留已有编译边界；新增交互的神经编码、门控、时序融合与输出修正参与编译。
动态邻居构建显式保持 eager；数据相关的动态操作可能造成图中断，不能把它理解为整模型 fullgraph。
编译不支持或编译失败时明确报错，不静默切换为整模型 eager。
本地 Windows/PyTorch 2.1 不支持 torch.compile，完整编译训练需在服务器验证。

日志与 `epochs.csv` 记录原路径准确率、最终/原路径/辅助损失、交互梯度范数、
修正 L2、编码边数、各区域候选启用率、邻居实际激活率与门控强度。
训练梯度范数是各 batch 反向传播后的范数平均，使用梯度累积时包含当前累计梯度。
验证损失是最终输出 CE，训练 loss 是优化的联合损失。

## 评估与交互消融

```bash
python tools/evaluate_best.py --checkpoint outputs/best_action_hand_body_ntu60_xsub/<run>/best.pt --device cuda
python tools/evaluate_best.py --checkpoint outputs/best_action_hand_body_ntu60_xsub/<run>/best.pt --device cuda --interaction-mode none
```

两种模式默认输出到不同目录。除逐类准确率和混淆矩阵，还输出候选启用率、实际激活率、
编码边数、修正幅度和同次训练原路径准确率。
`none` 会跳过所有交互边编码，得到**共同训练后的原路径**，不能把它当作独立训练的原最佳模型。
需另与独立从头训练的原架构比较，并关注穿脱鞋收益及阅读/写字等动作的变化。
