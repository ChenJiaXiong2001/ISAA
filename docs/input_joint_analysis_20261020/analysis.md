## 选点过程与失效原因

- 初始候选为 129 个原始点，68 个面部点固定保留；34 个门控制 54 个可选原始点，最低可到 75 点。相对 RTMW-133 少的 4 个点是原先固定候选布局的排除，不是本轮学习删除的结果。
- 第 1–5 轮确定性门值全部为 1，处于不加随机噪声及稀疏惩罚的热身期。
- 第 6 轮默认阈值名单曾降至 127 点；这是阈值导出记录，不是该轮已物理缩小网络。
- 第 7 轮恢复 129 点，第 8–100 轮确定性门值全部为 1。最佳与最后名单均无候选点被删除。
- 最佳 checkpoint 的原始门参数 mu 为 2.4602–3.0600；确定性门 clamp(mu, 0, 1) 全部变为 1。
- 在 sigma=0.5 时，预期激活概率 Phi(mu/sigma) 已接近 1。对保存的真实门参数做独立 autograd 检查，lambda=0.1 的归一化稀疏项梯度仅约 1.35e-11–8.17e-9。

可确认的问题是门参数跑进了全开饱和区，稀疏梯度已极弱。这与较晚、较弱的稀疏约束及无保留预算的目标有关；具体各因素的因果贡献仍需短实验区分。网络可以通过把门推高来减少随机门扰动，当前损失没有阻止最终全开。

这不是“提高导出阈值”能解决的：当前确定性门都等于 1，合法阈值小于 1 时全部保留。mu 的细微差别不能直接当作经验证的关节重要性排序。

此前的梯度/编译测试及小数据冒烟验证只证明路径可运行，并未证明默认超参数会在完整训练中收敛到稀疏子集；这方面的验收不足，需要补充实际删点率和饱和预警。

## 后续建议

保留此次 best 作为识别和失效对照，不继续照旧运行完整 compact。若目标仍是少节点输入，应新增带明确保留预算的选点实验，防止全开解，并使用单独门优化设置和饱和监控。先进行短程试验，检查门值分布、门梯度、实际保留数量及硬屏蔽后的准确率，再决定是否投入完整 100 轮。
