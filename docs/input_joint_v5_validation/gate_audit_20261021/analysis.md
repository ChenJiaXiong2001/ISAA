## 输入依赖及计算路径

运行配置记录 candidate_inputs=129、fixed_dependencies=75、optional_raw_nodes=54、gate_count=40、physical_compaction=false。

路由器仍从全部候选原始观测构造描述符和全局上下文。body/hand 编码仍使用原有张量尺寸；门是数值乘法，图结构没有被切小。面部仍先把 68 个原始面部点汇聚为 6 个 token，再运行编码器，最后才门控读出。固定身体依赖中还包含原始面部点 56。观测有效性、池化分母等也未随关闭门一并裁剪。

因此“13/60”是可选门的加权成本（身体权重1、双手组权重2、面部token权重1），不是最终输入只剩13个节点，不是删掉47/60的实际计算，也不是原始关键点检测阶段的节省比例。硬门准确率是在完整候选输入仍可用的条件下取得。

## 后续建议（本次未实施）

1. 如果目标是输入相关的动态选择，应先修复硬门退化为固定组合的问题；仅继续增大总节点惩罚没有保证，会更倾向于共享稀疏组合。应分别监测样本级硬模式数量、各类别开门率、准确率/成本权衡。
2. 如果目标是减少实际原始输入和推理计算，需要单独设计路由输入依赖与物理裁剪路径，再验证移除的观测不再进入路由、编码及有效性计算；用编译后的相同设备、batch、帧长对比baseline。
3. 当前证据不能证明关闭的手部/面部观测对所有动作无用，也不能证明关闭门后完全不依赖这些观测。需要进一步缺失输入/删除节点消融及重新验证。
